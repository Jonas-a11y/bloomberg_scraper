For the nerds — how the data is gathered

The short version

Bloomberg publishes a public ranking of the 500 wealthiest people at bloomberg.com/billionaires/, plus a profile page per person. A scheduler hits the list page on a cron and writes the current numbers to a local SQLite database. A separate one-shot backfill walks every profile page and pulls each person's full daily net-worth history (some go back to 2012). After backfill, the daily scrape continues to extend that history by one row per person per day. The database file is the source of truth; there's no third-party tracking or analytics in the page you're looking at.

The technical version

Sources. Both pages embed JSON inside <script> tags as JavaScript globals — window.top500 on the list page (an array of 500 person records with rank, net worth, asset breakdowns, biography, milestones, schools, etc.) and window.profileData on each profile page (the same record plus a stats array of [date, net_worth_usd] pairs going back to whenever Bloomberg first indexed that person).

Fetching. Bloomberg fingerprints non-browser TLS clients and serves a captcha page. curl_cffi impersonates Chrome's TLS handshake and HTTP/2 settings, so the responses come back as real HTML. A regex pulls the JSON literal out of the HTML and json.loads parses it.

Storage. Three tables in SQLite:

  • persons — static-ish fields (name, citizenship, biography, slug). Upserted on person_id.
  • snapshots — append-only time-series of rich data (rank, net worth, last/ytd change, public/private/cash asset totals + JSON breakdowns, liabilities) — one row per scrape per person.
  • wealth_history — narrow daily series, primary key (person_id, date). Idempotent: backfilling and the daily scrape both INSERT OR REPLACE into it.

Schedule. APScheduler runs cron-style jobs in-process. Each daily scrape pulls the list page, writes to persons and snapshots, and appends today's row to wealth_history — so the history stays current without ever re-fetching profiles.

Backfill. A background thread iterates every person, fetches their profile, parses stats, bulk-inserts to wealth_history. 1.5s sleep between requests keeps it polite — ~13 minutes for all 500. A "Sync from Snapshots" button copies any (person_id, date, net_worth) pair that exists in snapshots but not yet in wealth_history, catching the small gap between deploy and first backfill.

Derived fields. Bloomberg doesn't publish gender. We approximate it by counting gendered pronouns and role words in the biography (he / his / chairman vs she / her / chairwoman) and record a confidence score. Birth year is extracted from milestones[0] when it mentions "born", otherwise computed from age. Both are heuristics — treat them as hints, not facts.

Stack. FastAPI + Uvicorn (single port serves API and static frontend), SQLite, APScheduler, curl_cffi for fetching, Alpine.js + Chart.js for the UI. The whole thing fits in one Docker container with a mounted volume for the database.
